# 项目深挖与模拟面试：把知识变成可核查的证据

> 本章不对应原站文章，是知识库的补充章节（独立原创）

> **一句话结论**：面试准备最终交付的不是读完的章节数，而是能被追问到代码、数据与失败复盘的项目证据包。先做实操，再用一轮模拟暴露缺口，回到对应主题补，不另建一份重复题库。

## 「这些原理我都懂，怎么证明不是看过教程？」

每个结论都给证据：哪段代码负责、在哪种输入下失败、怎么测出改进、用了什么基线。读过 LoRA 不等于做过后训练，画过 outbox 不等于上线过任务系统；明确说出没做过什么，比用术语填满简历更可信。

## 动手：把 mini Claude Code 变成你的面试项目

面试最怕的是项目讲不深。你已经跟着第 4 部分做过一个 mini Claude Code，它天然就是一个好项目：从 0 长到 21 个能力，每一步都有代码和测试。

问题在于，「我跟着教程写了一个 Claude Code」这句话本身没有说服力。要把它讲成面试项目，得补上三样东西：

1. **一个你自己定的指标。** 比如给它加一份 20 道题的小评测集，统计改动前后的通过率和平均 token。没有指标，项目深挖问到「效果怎么样」就答不上来。
2. **一次真实的取舍。** 比如压缩阈值为什么定在这里、记忆为什么选文件而不是向量库。面试官追问五层，追的就是这些决定背后的理由。
3. **一次失败。** 比如某次改提示词后，它开始一读文件就停不下来，你是怎么从 trace 里发现、怎么修好的。失败复盘要准备到能解释证据、原因与取舍。

可以用下面这个模板准备项目深挖稿，每一栏写两三句：

```text
项目一句话：      一个带 21 项能力的终端编码 agent（mini Claude Code）
我负责的部分：    全部；重点讲 compact、权限审批、sub agent 三块
关键指标：        自建 20 题评测集，pass^3 从 __% 提到 __%；平均每题 token __
最难的问题：      __（一句话现象）→ 根因 __ → 修法 __
一次取舍：        __ 选了 A 没选 B，因为 __；代价是 __
如果重做：        __
```

写完分别拿[Agent 机制](03-agent-mechanisms.md)和[生产工程](04-production-engineering.md)的追问自检：哪些有自己的例子，哪些只有概念？算法岗位再补[模型训练](02-model-fundamentals.md)的数据、实验与消融证据。

## 不同岗位的项目证据不能互相冒充

| 方向 | 至少展示 | 不足以代替它的材料 |
|---|---|---|
| 应用 / Harness | 循环与工具实现、失败 trace、质量/成本对照、安全边界 | 框架截图、只有成功样例的演示 |
| AI 全栈 | 浏览器到 worker 的闭环，断线、取消、重投、租户隔离测试 | 只会打字的聊天 UI、只有架构图 |
| 算法 / 后训练 | 合规数据来源、训练配置、基线、消融、未见任务和回归 | 调过 API、做过标量公式实验 |
| 推理 / 训练平台 | 指明硬件与负载的吞吐/延迟/内存、恢复与调优记录 | 背 vLLM / FSDP 名称、不注明条件的 benchmark |

## 编码和实操题

| 题目 | 难度 | 怎么准备 |
|---|---|---|
| 手写 ReAct loop，或写 agent loop 的伪代码 | L2 | 不看书写一遍 [Coding Agent](../p2-agent-basics/02-coding-agent.md) 的循环，带步数上限和错误回填 |
| 用 numpy 手写多头注意力 | L2 | [token 预测](../p0-core/04-llm-token-prediction.md)的「动手」用 numpy 写了一层单头因果注意力（`TinyAttention`，打分在 `code/agent/core/next_token.py` 的 `_logits_last`）。本库只写到单头，多头（拆头、各自算注意力、拼接再投影）需要自己扩展 |
| LeetCode：合并有序数组、判断链表有环、编辑距离 | L1 | 传统编程可能仍被考察，按目标岗位单独练，不作频率保证 |
| 调试题：这个 agent 在某些输入上无限循环，找原因并修好 | L2 | [Agent 循环与诊断](03-agent-mechanisms.md)；练习读 trace |
| Take-home：给 50 篇 Markdown，搭问答系统和 20 题评测集，报告 recall@5 和 faithfulness | L2 | [RAG 问答机器人](../p2-agent-basics/03-rag-qa-bot.md) 搭系统，[RAG 评测](../p3-agent-internals/16-rag-eval.md) 建评测集、算 recall@k 和 faithfulness |
| Take-home：多跳文档问答加引用追踪，或者带准确率评测的代码审查 agent | L2 | 同上，重点是评测和 README |
| 实操类编码：内存数据库、多阶段题 | L2 | 工程基本功 |

## 项目深挖和行为面

| 题目 | 难度 | 怎么准备 |
|---|---|---|
| 为什么转做 Agent；平时用哪些 AI 工具，学到了什么 | L1 | 准备一个具体的使用心得，比如你写过的某个 hook 解决了什么问题 |
| 项目是从零做还是基于开源；最难的问题是什么，你负责哪部分，结果如何 | L2 | 用本章的项目稿模板准备 |
| 这个 agent 怎么实现的；团队用什么模型、几个人 | L2 | 能追问到代码层 |
| 客户说 bot「感觉很笨」，你先改什么 | L2 | 先看 trace 归类失败，再决定改提示词、工具还是检索 |
| 讲一个失败的实验；你对模型有什么看法 | L2 | 准备一次真实的失败复盘 |

## 一轮 45 分钟模拟，要同时验证横向知识与纵向深度

下面是自拟演练节奏，不是企业统一流程。让同伴提问，或自己录音；每次只选一个主场景，避免在四十五分钟里机械覆盖所有缩写。

| 时间 | 要求 | 验收点 |
|---|---|---|
| 0–5 分钟 | 用两分钟介绍项目，再澄清目标岗位的核心职责 | 个人贡献、指标与边界明确，没有把团队成果全算自己 |
| 5–13 分钟 | 一道模型题加一道 Agent 题，各连续追问两层 | 解释机制、给例子、说明失效条件；不只报框架 |
| 13–25 分钟 | 从系统设计章选一道题完整展开 | 需求、状态、副作用、安全、评测都能闭环，每步说代价 |
| 25–35 分钟 | 现场写 / 调试一个小模块 | 能运行的边界测试；不能只口述“加个锁/重试” |
| 35–42 分钟 | 追问一次失败实验与一次上线故障 | 现象、证据、根因、修法和回归能互相对上 |
| 42–45 分钟 | 总结最弱两项与下一步 | 区分不懂机制、没有实现、缺效果证据 |

算法路线把更多时间给数据、loss、训练稳定性与消融；全栈路线把更多时间给交互恢复、数据库和外部副作用；平台路线补资源与调度。不改变安全与证据底线。

## 评分要看证据级别，不凭表达流畅判断

每个问题记录 0–3 分：0=答不出；1=能解释概念；2=能说明实现、边界与代价；3=有可复现代码/实验和失败证据。分数仅是自测量尺，不是企业录用阈值；岗位核心项停在 1 分，就不能用其他术语数量补偿。

复盘表每行只留：问题 → 当时卡点 → 应回到的章节 → 下一份可交付证据。用[模型](02-model-fundamentals.md)、[Agent](03-agent-mechanisms.md)、[生产工程](04-production-engineering.md)和[系统设计](05-system-design.md)作为唯一主题入口，别再抄一份平行知识库。

## 对照你的环境

你的工具链、日常 webapp 和 mini Claude Code 都可以提供真实素材。选一个自己负责的改进，讲清从发现失败到验证发布的链路；离线 fake 输出只能称工程验证，线上质量数字必须有真实来源和授权。

## 常见坑

- **项目贡献边界不清。** “我们做了”后面要能区分自己实现、参与设计和仅使用的部分。
- **把性能数字当常数。** 硬件、模型、数据、并发和测量方法都要保留。
- **复盘只说“后来优化了”。** 必须说是什么证据排除了其他解释。
- **模拟只练口述。** 留出写代码和测试时间，才能发现工程基本功缺口。

## 练习

**1.** 完成一页项目证据包，删掉无法给出出处的数字。

<details><summary>提示</summary>

至少包含贡献边界、基线、评测集/负载、实现位置、一次失败和未完成项。20 题小评测可用于起步，不把小样本提升泛化成普遍能力。

</details>

**2.** 从实操表选一道题，不看教程实现并写失败测试。

<details><summary>提示</summary>

优先选择和岗位相关的一个：有上限的工具循环、断线重放 reducer、幂等动作账本或训练数据 mask 检查。计时后保留未完成边界，别把计划算成实现。

</details>

**3.** 开放题：模拟中概念题都能答、项目追问都卡住，下一周怎么准备？

<details><summary>提示</summary>

不要继续扩名词表。选一个真实失败完成复现、定位、修改、验证和文档记录，再带着同一问题重新模拟，观察是否从概念证据升级为实现与效果证据。

</details>

回到开头：面试不是证明你用过多少 AI 工具，而是证明你能理解、实现、验证并承担系统结果。回到主线：围绕模型有限上下文做出的每个工程决定，都能解释机制、代价与证据，才算把这一部分学完。
