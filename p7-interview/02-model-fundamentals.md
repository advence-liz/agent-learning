# 模型原理与训练：从 token 预测到预训练、后训练

> 本章不对应原站文章，是知识库的补充章节（独立原创）

> **一句话结论**：预训练建立基础能力，后训练塑造指令遵循、偏好和任务行为；LoRA 是「改哪些参数」，SFT、DPO、GRPO 是「拿什么信号来学」，不是同一层的替代选项。应用岗要能选方案，训练岗还必须拿出实验与系统实现证据。

## 「调用模型、让模型变强，是同一回事吗？」

不是。推理是在给定参数下生成，训练通过学习信号更新参数；应用工程师要能解释两者如何影响 Agent 行为，训练岗还要拿出数据、实验与系统实现。本章按“推理机制 → 训练阶段 → 对齐算法 → Agent 数据与评测”串起来，而不是把预训练和后训练作为额外八股。

先回答一个推理问题：从已有 token 到下一个 token，中间为什么需要 attention、KV cache 和采样？

## 模型基础不只背 Transformer，要能联系推理瓶颈

**追问：Attention 的 Q、K、V 与 mask 在做什么？**

Q 是当前位置用于匹配的查询，K 是可被匹配的位置表示，V 是聚合的内容表示。缩放点积注意力可写为：

$$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}(QK^T/\sqrt{d_k}+M)V$$

因果 mask 阻止当前位置看到未来；位置编码补足顺序信息。Transformer 还包括前馈网络、残差与归一化等，不能把整层说成只有 attention。多头让不同子空间学习不同关联；GQA 共享部分 KV 头，可以减少 KV 缓存规模。[9]

训练时已知目标序列，在因果 mask 下可并行计算多个位置的损失；自回归生成则要等新 token 产生才能继续。temperature、top-p 改变采样，不保证低温时每次完全一致，也不能解决权限或事实问题。基础流水线见 [LLM 推理全流程](../p6-nn-llm/05-inference-process.md)。

**追问：prefill 和 decode 分别慢在哪？**

prefill 处理输入前缀并建立 KV cache；decode 在已有缓存上逐步生成。前者常有较高计算强度，后者常受权重 / KV 读写带宽影响，但具体瓶颈要看硬件、batch、模型和长度，不能绝对化。

TTFT（time to first token）还包含排队、网络和前处理；TPOT（time per output token）反映逐 token 速度，端到端延迟还取决于生成长度和工具耗时。平均延迟不足以承诺体验，要看 p95 / p99、超时率及任务类型切片。

**追问：模型权重放得下，为什么长上下文仍然 OOM？**

除权重外还有 KV cache、激活、运行时缓冲与碎片。粗估标准 decoder KV cache（不计分片、压缩等）为：

$$2\times L\times T\times H_{kv}\times d_{head}\times b$$

2 是 K 与 V，L 是层数，T 是当前 batch 各序列已缓存 token 数之和，$H_{kv}$ 是 KV 头数，$d_{head}$ 是头维度，b 是每元素字节数。并发与上下文长度一起涨，就会吃掉显存。

例如 32 层、8 个 KV 头、头维 128、每元素 2 字节，总计 8192 个缓存 token，理论 KV 量是 **1 GiB**；这不是整个推理进程的显存量。GQA 模型不能误用 query 头数估算缓存。


## 训练阶段不是所有模型必走的一条流水线

```d2
direction: down
corpus: "大规模语料\n去重、过滤、混合"
base: "预训练\n得到基础模型"
cpt: "持续预训练（可选）\n领域文本 / 代码"
sft: "SFT（常见后训练步骤）\n指令与正确示范"
dpo: "DPO 等偏好优化\n离线 chosen / rejected"
rl: "在线 RL（如 GRPO / PPO）\n采样、环境反馈、更新策略"
corpus -> base: "自监督目标"
base -> cpt: "可选领域适配"
base -> sft: "可以直接开始"
cpt -> sft: "常见路径"
sft -> dpo: "一种改进行为的路线"
sft -> rl: "另一种路线，也可与偏好优化组合"
```

读图：后训练（post-training）是一个阶段集合，不等于「SFT 之后才叫后训练」；图画的是常见路线，不是强制顺序。[1][2][3]

| 名词 | 数据 / 学习信号 | 主要在学什么 | 面试不能混淆的边界 |
|---|---|---|---|
| 预训练（pretraining） | 大规模文本、代码等；对因果语言模型通常做下一个 token 预测 | 语言、知识、模式及基础能力 | 不是人工给每条文本配答案；也不是所有模型都用因果目标 |
| 持续预训练（continued pretraining，CPT） | 从已有 checkpoint 继续吃领域语料 | 适应领域分布、术语与代码 | 不是 RAG，也不保证事实精确可查；要防通用能力遗忘 |
| 监督微调（supervised fine-tuning，SFT） | 指令、对话、工具轨迹中的目标输出 | 模仿高质量任务行为 | 不等于换了预测机制；通常仍是 token 级交叉熵 |
| 偏好优化（以 DPO 为例） | 同一输入的较好 / 较差回答 | 调整相对偏好 | 不需要先单独训练一个显式奖励模型；也不是简单只对 chosen 做 SFT |
| 强化学习（reinforcement learning，RL） | 策略采样的回答或轨迹，加奖励反馈 | 优化任务回报 | 奖励变高不自动等于能力提升，可能在钻评分漏洞 |

预训练像广泛读书，SFT 像看老师示范，偏好优化像比较两份答案，在线 RL 像做题后按反馈改策略。类比只解释学习信号：模型不是人，不能由此推导它「理解了」或一定泛化。

**面试追问：SFT 和预训练不都在预测下一个 token 吗？**

是的，对这里讨论的因果语言模型，底层都可以用交叉熵。区别在数据分布、条件结构、训练阶段与 loss 覆盖哪些位置。SFT 常只监督 assistant / completion 的 token；用户输入和工具观察可以作为条件，而不作为本次要模仿的目标。具体 mask 要检查数据整理器和 chat template，不能靠字段名猜。[2]

## LoRA、量化与蒸馏回答的是不同的问题

| 方法 | 回答的问题 | 要能讲清的代价 |
|---|---|---|
| 全参数微调 | 是否更新整个模型 | 权重、梯度、优化器状态与激活的显存成本 |
| LoRA | 是否只训练低秩适配器 | 冻结基座，学习低秩增量；省可训练状态，不代表不存基座或激活 |
| QLoRA | 能否在量化基座上训练适配器 | 基座低比特存储并结合相应计算；不等于把全部训练运算都变成 4 bit |
| 量化（quantization） | 权重 / 激活等用多低的数值精度 | 省内存可能换来精度或算子兼容损失；需按任务复测 |
| 蒸馏（distillation） | 能否把教师行为或分布迁移给学生 | 依赖教师质量、覆盖面与学生容量；不只一种训练损失 |

所以「我们用 LoRA 做 SFT」完全合理；也可以用适配器做偏好优化。LoRA 的公式和实跑结果回看[动手用 LoRA 微调模型](../p6-nn-llm/06-lora-fine-tuning.md)，这里不重复实现。QLoRA 和蒸馏的论文见延伸阅读。[5][6]

## 先把 RL 的奖励、价值与优势接起来

在 Agent 任务里，状态 / 观察是当前可用信息，动作是生成 token 或发起工具调用，环境返回观察与奖励。真实世界未必完全可观测，别把一段对话等同于完整世界状态。

| 概念 | 大白话 | 和训练更新的关系 |
|---|---|---|
| 策略（policy） | 在当前条件下选各个动作的概率分布 | 语言模型本身可当作策略，参数更新会改变动作概率 |
| 奖励（reward） | 某一步或任务结束时得到的反馈分数 | 不等于真实业务价值，评分器可能被钻空子 |
| 回报（return） | 从当前时刻起，未来奖励的加权累计 | 常写为 $G_t=\sum_{k\geq0}\gamma^k r_{t+k}$，有限任务也可不折扣 |
| 价值（value） | 当前策略下，从某状态出发的预期回报 | critic 常用来估计基线，不是最终答案是否正确的同义词 |
| 优势（advantage） | 某动作相比当前基线好多少 | 常写为 $A(s,a)=Q(s,a)-V(s)$，正负信号用于调整策略 |
| 策略梯度（policy gradient） | 用采样动作的对数概率梯度与回报 / 优势构造估计 | 不是对离散采样动作本身求导，也不是把环境打分器直接当可微损失 |

PPO 用优势估计与裁剪等手段限制策略更新幅度；经典 actor-critic 路线还要学习价值估计。GRPO 改用同一问题下的一组采样结果构造相对基线，不是「没有 critic 就没有基线」。这里是理论入口，不覆盖策略梯度推导、GAE 或完整优化器复现；训练岗继续读 [PPO 论文](https://arxiv.org/abs/1707.06347)与 [Sutton & Barto 教材](http://incompleteideas.net/book/the-book-2nd.html)。

## RLHF、DPO、PPO、GRPO 要按信号与优化方法来比较

RLHF（reinforcement learning from human feedback）描述利用人类反馈改进行为的范式。经典路线是：偏好数据 → 奖励模型 → 用 PPO 等算法更新策略，并约束不要偏离参考模型过远。PPO 不是 RLHF 的同义词。[3][7]

RLAIF 把部分反馈来源换成 AI；RLVR 强调可验证奖励，例如测试通过或数学答案正确。**反馈谁给、怎么打分、用什么算法更新**是三条不同的轴，不能把这些缩写放在同一层互斥分类。

| 比较项 | 经典 PPO 式 RLHF | 标准离线 DPO | GRPO 式在线训练 |
|---|---|---|---|
| 训练时是否生成新样本 | 通常需要 | 可直接用固定偏好对 | 需要，同一输入采样一组输出 |
| 奖励来源 | 常见是学到的奖励模型 | chosen / rejected 偏好对，隐式表达奖励 | 规则、验证器或奖励模型都可以 |
| 单独价值模型 | 经典 PPO 路线常有 critic | 不需要 | 原始 GRPO 不需要单独 critic，用组内基线 |
| 参考模型 / 约束 | 常用 KL 约束等防漂移 | 标准目标比较策略与参考模型的对数概率比 | 是否使用参考 KL、如何裁剪，取决于实现与配置 |
| 最该担心什么 | 奖励黑客、训练不稳定、采样成本 | 偏好数据偏差、分布外泛化、偏好过拟合 | 组内无奖励差异、奖励漏洞、长轨迹成本与归因 |

**DPO 的最短原理答法**：同一输入下，计算 chosen 与 rejected 相对于参考模型的对数概率改变量之差，再优化一个偏好分类目标。它优化的是相对偏好，不保证 chosen 的绝对概率一定上升。[3]

**GRPO 的最短原理答法**：同一问题采样多份答案，用组内奖励比较估计优势，再做受约束的策略更新。所有答案都得同一分时，组内相对信号为零；不是「多采样几次就必然学得更好」。优势怎么归一化、是否加 KL，不同版本有变体，要说明你用的配置。[4]

### 动手：不加载模型，也能验证两个目标的信号

下面只是**离线标量教学实验**，不是 DPO / GRPO 训练器；不含模型、梯度、策略比裁剪与环境交互。复制到 Python 终端即可运行，不依赖第三方库，也不调用 API。

```python
import math
import statistics


def dpo_loss(policy_gap, reference_gap, beta=0.1):
    # gap = log p(chosen | x) - log p(rejected | x)
    z = beta * (policy_gap - reference_gap)
    # 稳定计算 -log sigmoid(z)
    return max(-z, 0.0) + math.log1p(math.exp(-abs(z)))


def relative_signal(rewards):
    # 只示意组均值中心化，不是完整 GRPO 优势实现
    mean = statistics.mean(rewards)
    return [round(r - mean, 2) for r in rewards]


print(f"DPO baseline={dpo_loss(0, 0):.4f}")
print(f"DPO preferred_margin_up={dpo_loss(2, 0):.4f}")
print("group varied=", relative_signal([0, 0, 1, 1]))
print("group tied=", relative_signal([1, 1, 1, 1]))
```

本次实跑输出（离线标量计算，无模型）：

```text
DPO baseline=0.6931
DPO preferred_margin_up=0.5981
group varied= [-0.5, -0.5, 0.5, 0.5]
group tied= [0, 0, 0, 0]
```

说穿了，目标函数必须收到能区分行为好坏的信号。把错误答案标成 chosen，或让所有轨迹都拿满分，再漂亮的训练框架也救不了。

## Agent 后训练的难点，是轨迹与环境，不只是换个 loss

**面试题：让模型学会查订单和退款，你会准备什么数据？**

强回答要从一次完整任务讲起，而不是说「收集问答对」。至少保留：用户目标、可用工具及其 schema、assistant 的工具调用、工具观察、后续动作、最终结果；记录工具 / 环境版本、数据来源与使用许可。工具返回内容是观察，不应无脑作为 assistant 的模仿目标。[2][3]

可以用同一个退款任务对比三种信号：

- **SFT**：给出一条经过验证的正确轨迹，教模型先查订单、再核验资格、经授权后退款；也包含不该调用工具、缺信息时澄清、工具失败后恢复的示范。
- **DPO**：同一任务下，选择「核验后正确处理」而不是「未授权就退款」。偏好标准要包含正确性与安全，不只是措辞更客气。
- **在线 RL**：在隔离的模拟订单环境里让模型交互，按最终订单状态、授权和规则满足情况给奖励。不能直接让探索策略对真实客户反复退款。

**面试追问：奖励怎么设计？**

先验证任务最终状态，再看格式、步数、延迟和成本。只奖「返回成功」会诱导模型假报完成；只奖工具成功率会让它不调工具；只奖少步数会让它跳过核验。对不可接受的越权操作，环境硬拦，不能寄希望于一个很大的负分替代权限控制。

长任务还会遇到稀疏奖励与信用分配（credit assignment）：最后成功不代表每一步都对。需要可重置的环境、轨迹检查、合理的过程信号，并用未见任务验证是否只学会了刷奖励。

## loss 下降只证明拟合，不证明能上线

**面试题：训练 loss 降了，测试效果却差了，怎么查？**

按四层查，比立刻换学习率更有说服力：

1. **数据层**：重复、错标、敏感信息、分布偏移、模板泄漏。按任务来源 / 时间 / 用户或模板族切分，不能把同一轨迹的改写分到训练和测试两边；测试集不参与选超参。
2. **实现层**：tokenizer 与 chat template 是否一致；EOS、padding、label shift、loss mask、截断是否正确；多轮工具调用是否被截断成了坏协议。
3. **优化层**：过拟合、遗忘、学习率、有效 batch、梯度、KL / 熵、奖励分布；比较基座、SFT、偏好优化等消融，别把多种改动一起归功于一个算法。
4. **业务层**：固定未见任务，看任务成功、工具参数、越权、拒答、延迟与成本；加通用能力回归。离线胜率提升后还要灰度、监控和回滚。

蒸馏数据、人工反馈和线上 trace 都必须有授权、脱敏和保留策略。看过日志不等于可以把日志用于训练。

### 「OOM 怎么办」要知道省的是哪一块

训练显存不只是参数：还包括梯度、优化器状态、激活与临时缓冲。先量，再选办法。[8]

| 手段 | 主要解决什么 | 换来的代价 |
|---|---|---|
| 缩短序列 / 减小 micro-batch | 激活等峰值开销 | 上下文覆盖、吞吐或梯度噪声变化 |
| 梯度累积 | 小 micro-batch 下扩大有效 batch | 不消除每步激活；还涉及更新频率与吞吐 |
| 混合精度 | 部分张量与计算成本 | 数值稳定性与硬件支持 |
| 激活重计算 | 少存激活 | 用额外计算换内存 |
| DDP | 数据并行提高吞吐 | 每卡仍常驻模型副本，不是模型放不下的万能解 |
| ZeRO / FSDP | 分片训练状态 | 通信、聚合和 checkpoint 管理复杂度；ZeRO 1/2/3 分别进一步分片优化器、梯度、参数 |
| 张量 / 流水线并行 | 拆层内计算 / 按层切模型 | 通信、调度与流水线空泡 |

断点恢复还要保存优化器、调度器、随机状态及数据进度，不是只保存最终 adapter。这里提供原理辨析，**没有多卡训练实跑**；训练岗还需补真实集群实验、吞吐分析与复现报告。

## 怎么把这章用在你现有的项目里

你写的 skill 和提示词改变当次上下文，SFT 改变模型参数；长期记忆存了信息，也不等于模型权重已更新。面试被问「为什么不直接微调」时，可以这样答：

> 先用失败集确认瓶颈。动态、可追溯、按权限更新的事实优先检索；稳定重复的格式或行为问题，在有足够合规数据和可控模型时考虑 SFT；有可靠偏好对或可验证环境后，再评估偏好优化或 RL。训练不是检索、权限与评测的替代品。

回到开头：做过 LoRA 是一块证据，不是覆盖训练全链路的证明。回到主线：上下文工程改变模型「这次看到了什么」，训练改变「看到这些 token 后更倾向怎么继续」；两层都要靠评测检验。

## 常见坑

- **把后训练说成 SFT 的后一步。** SFT 本身通常就是后训练的一种。
- **把 DPO 说成完全不需要参考、GRPO 说成永远有 KL。** 先说明标准目标，再区分实现变体。
- **只拿成功轨迹训练。** 会遗漏不应执行、澄清、拒绝和失败恢复等行为。
- **用 loss 或训练奖励代替业务评测。** 泛化、权限安全与成本必须单独测。
- **把概念实验包装成训练经验。** 下面的标量练习不等于复现了任何模型训练。

<details><summary>提示</summary>

按「更新哪些参数 / 用什么信号 / 信息存在权重还是上下文」三条轴回答。若说成「LoRA 比 SFT 省显存」但没说明比较的是全参数 SFT，就还没分清。

</details>

**2.** 给退款 Agent 各设计一条 SFT 样本、一对偏好轨迹、一个可被钻空子的奖励，并修正奖励。

<details><summary>提示</summary>

检查工具 schema、授权、环境初始状态和最终订单状态是否明确；偏好对的任务前提要相同。修正奖励后，仍需环境权限硬闸与未见任务测试，不能只改分数。

</details>

**3.** 开放题：SFT 任务正确率上升，但通用对话能力下降，你如何决定是否发布？

<details><summary>提示</summary>

先按切片定位遗忘或分布变化，检查数据与模板，再做配比、学习率或训练步数消融。预先设定回归下限、灰度与回滚条件；「业务分涨了」不能自动覆盖安全退化。

</details>
