# 二维 0/1 背包

> [算法路线](00-guide.md) · 独立原创

**同时受两种独立资源限制时，剩多少重量额度不能代表还剩多少体积额度。** 把两个容量都放进状态；每件物品只能拿一次，因此「拿这件」必须从上一层转移。

- [写清容量语义](#method)：两维都表示上限，不要求恰好装满。
- [看见轮次关系](#worked-example)：原地转移不能读到当前物品刚写出的值。
- [手算并验证](#verify)：比较可行组合，再测复用反例。

## 两个容量同时约束才是一个完整状态 { #method }

有 `n` 件物品，每件至多取一次。物品 `i` 消耗非负整数资源 `(w_i,v_i)`，收益为 `g_i`（允许负收益），总消耗分别不得超过非负整数容量 `(W,V)`。可以不选物品，不要求恰好等于两个容量。

令 `D_i[a,b]` 表示只看前 `i` 件、两种容量上限为 `a,b` 时的最大收益。`D_0[a,b]=0` 对所有容量成立。不拿第 `i` 件沿用 `D_{i-1}[a,b]`；若 `a≥w_i` 且 `b≥v_i`，可再比较 `D_{i-1}[a-w_i,b-v_i]+g_i`。任一可行解恰属于拿或不拿之一；拿的情形删掉这一件后，剩余物品仍满足收紧后的容量。

## 双维倒序让原地转移仍然读取上一层 { #worked-example }

```text
D 全部初始化为 0
对每件物品 (w,v,g)：
    a 从 W 降到 w：
        b 从 V 降到 v：
            D[a,b] = max(D[a,b], D[a-w,b-v] + g)
返回 D[W,V]
```

如果 `w>0`，来源在更小的 `a` 行，该行本轮还没动；如果 `w=0` 且 `v>0`，靠 `b` 倒序保证来源仍旧；如果两个消耗都是 `0`，每个格只更新一次，读取的是自己写入前的值，仍只加一次收益。若用两张表分开存上一轮和当前轮，容量方向则不受限制。时间 `O(n(W+1)(V+1))`，空间 `O((W+1)(V+1))`；复杂度依赖于容量的数值，不是其位数。

## 最贵的单件可能挡住更好的组合 { #verify }

容量 `(4,4)`，物品 `A=(2,1,5)`、`B=(1,3,6)`、`C=(3,2,8)`，三元组分别是两种消耗和收益。

| 已处理物品 | `D[3,3]` | `D[4,4]` |
| --- | --- | --- |
| 无 | `0` | `0` |
| A | `5` | `5` |
| A、B | `6` | `11` |
| A、B、C | `8` | `11` |

拿 `A+B` 要 `(3,4)`，因此只在右列可行。轮到 `C` 时，右列试取的来源是旧 `D[1,2]=0`，于是候选只有 `8`；`A+C` 重量超标，`B+C` 体积超标。

- **边界练习**：容量 `(0,2)`，两件物品 `(0,1,3)` 和 `(0,0,5)`，应得 `8`。检查零重量物品不会被容量边界漏掉，零消耗物品也只拿一次。
- **遍历反例**：只有一件 `(1,1,4)`，容量 `(2,2)`。两个维度都升序会先把 `D[1,1]` 写成 `4`，随后从它写出 `D[2,2]=8`，非法。正确值为 `4`。
