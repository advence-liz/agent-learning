# 哈希表实现：桶内碰撞和扩容是性能账的两半

> [算法路线](00-guide.md) · 独立原创

**哈希值决定先查哪里，相等判断才决定找没找到。** 不能把哈希值当唯一 ID。

## 用冲突样本推导桶结构

设整数哈希简化成 `((x % 4)+4)%4`，`1,5,-3` 全部在桶 `1`。采用链地址时，每个槽存若干键值对；读写先算桶号，再按该桶的键等价规则查找。更新 `5` 不新增一对。开放寻址改为沿探测序列找槽；删除通常要放墓碑而不能清成从未使用，否则查询会在墓碑之前截断已有键的探测序列。

负载因子是已有元素与桶数的比值。平均散列均匀且控制负载时，短链带来平均常数访问；如果所有键集中在一个桶，最坏一次 `O(n)`。桶数翻倍时所有键需要按新容量重定位，不能直接复制槽下标；某次扩容 `O(n)`，几何级数保证连续插入的搬运总量 `O(n)`。这不是对任意 JavaScript `Map` 实现的内部布局断言。

练习：桶数由 `4` 翻到 `8`，`1,5,-3` 分别去哪？更新 `5` 后元素数是否增加？
