# 第三实战：把路径查询拆成建模、选算法和校验结果

> [算法路线](00-guide.md) · 独立原创

**可解释的路径接口不仅要报成本，还要交付一条能重算该成本的路径。** 根据边权性质选 BFS、Dijkstra 或负权算法，别靠「图上都能用」的模板。

## 约定同一模型，再拿两种算法交叉验证

做一个离线路线查询器，输入邻接表、出发点、目的地。第一轮只支持单位边，保存首次发现时的前驱；第二轮支持非负权，每次严格松弛时更新前驱。返回 `null` 表示不可达；起点等于终点时返回只有起点的路径和成本 `0`。同权重多路径可以返回任意一种最优解，但要把平局口径写在接口里。若允许并行边，路径应带边 ID 或成本，不能只靠顶点列表再随便找第一条边。

图 `S→A(4), S→B(1), B→A(0), A→T(2), B→T(9)` 的最短成本为 `3`，路径 `S→B→A→T`。删 `A→T` 后应走 `S→B→T`、成本 `10`；若再删 `B→T` 则不可达。

练习：用全为 `1` 的小图比较 BFS 和 Dijkstra 距离，然后故意造一个「直接一步更贵」的失败用例。
