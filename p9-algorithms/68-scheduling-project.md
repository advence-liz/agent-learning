# 第二实战：给日程服务做可验证的区间查询

> [算法路线](00-guide.md) · 独立原创

**同一批日程，用贪心选最多、扫描线算峰值、堆分配房间，三个功能应共享边界契约而不是共享同一个算法。**

## 先写接口和验收表，再优化

输入是一组非空半开区间和稳定的日程 ID。实现 `maxCount()`、`peakLoad()`、`assignRooms()`：第一个返回最多互不重叠的数量；第二个返回同时占用峰值；第三个给每场分配房间编号，允许已结束房间复用，且实际使用的不同房间数等于峰值。简单版本 `assignRooms` 可按开始时间线性找可用房间，复杂度最坏 `O(n²)`；优化后可以维护进行中的结束堆与空闲房间集合，时间 `O(n log n)` 量级。

| 用例 | 最大相容数 | 峰值 |
|---|---:|---:|
| `[]` | 0 | 0 |
| `[1,3),[3,5),[2,4)` | 2 | 2 |
| `[1,10),[2,3),[4,5),[6,7)` | 3 | 2 |
| 三个完全相同的非空区间 | 1 | 3 |

练习：为 `assignRooms()` 写与具体编号无关的性质测试，再证明没有比峰值更少的分配。

<details>
<summary>验收提示</summary>

先按分配结果分组，核对每场恰出现一次，每组按开始时间排序后满足 `prev.end <= next.start`。同时重叠的会议必占不同房间；只有所有现有房间都在忙时，才需要新增一间。
