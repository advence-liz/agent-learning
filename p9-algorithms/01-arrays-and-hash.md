# 数组、哈希与前缀和：把重复计算变成查表

> [算法路线](00-guide.md) · 独立原创
>
> **一句话：**寻找「以前见没见过」用哈希索引；反复问「这段加起来是多少」用前缀和。两种做法都用额外空间减少重复扫描，但保存的是不同的信息。

## 先看结果，再问为什么不必扫两遍

给日志耗时 `[3,-2,7,0]`（允许有修正项），反复统计某段的和；再给编号 `[4,4,9]`，找两个不同位置的值加起来等于 `8`。直接枚举容易写，但前者每个查询都重加一遍，后者最坏试约 `n²/2` 对。从仓库根目录运行：

```bash
node code/algorithm-node/examples/01-arrays.ts
```


## 哈希表只记录当前项之前的候选

扫到 `j` 时，要找的是 `target - values[j]`。只要 `Map` 存着此前的值及其下标，就能一次查补数。先查再写：`[4]` 不可能与自己成对；`[4,4]` 则会在第二项命中第一个下标。只需找任意一对，因此同值出现多次时留下最近位置也够用。

```ts
const seen = new Map<number, number>();
for (const [j, value] of values.entries()) {
  const i = seen.get(target - value);
  if (i !== undefined) return [i, j];
  seen.set(value, j);
}
```

时间复杂度（time complexity）看操作次数随规模如何增长。两层枚举最坏 `O(n²)`，额外空间 `O(1)`；按哈希访问平均 `O(1)` 估算，查表法时间、额外空间都是 `O(n)`。**别写 `if (i)`**：有效下标 `0` 为假值。示例按普通整数算术讨论，输入和中间结果需在 JS 精确整数范围内。

## 前缀和记录的是边界之前的累计值

| 边界 `i` | 0 | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|---:|
| `prefix[i]` | 0 | 3 | 1 | 8 | 8 |

`prefix[i]` 表示前 `i` 项，也就是区间 `[0,i)` 的和。问 `[1,3)`，取 `prefix[3] - prefix[1] = 8 - 3 = 5`。左边界为 `0`、空区间以及右边界为数组长度都用同一公式。建表 `O(n)` 时间和空间，之后每次查询 `O(1)`；如果只有一次短区间查询，直接求和更划算。原数组有更新时，旧表不会一起变。

[完整实现](../code/algorithm-node/src/arrays.ts)约定 `0 <= left <= right <= n`，不替调用者修正错传的边界。
