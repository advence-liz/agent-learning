# 算法导读：先说清状态，再背模板

> **一句话：**先把暴力解写明白，再用输入条件减少工作量；每学一种方法，都要能说出它维护了什么、为什么没漏解、怎样用反例验证。只需要一点 TypeScript，不用先学 Agent，也没有模型调用。

选题参考 labuladong 的[算法首页](https://labuladong.online/zh/algo/home/)和[学习路线](https://labuladong.online/zh/roadmap/algo/)。本路线重新编排，课程、示例、练习与项目均独立编写。

- [先学会排除候选](#narrow)：用查表、区间和指针替代重复扫描。
- [再学会组织遍历和决策](#traverse)：决定下一步处理谁，以及哪些分支不必再算。
- [最后把能力接成一个项目](#build)：用一个规划器检验图与堆是否真的学会了。

<a id="narrow"></a>

## 先用输入条件缩小问题，而不是上来就套模板

| 学什么 | 一道题带走什么 |
|---|---|
| [数组、哈希与前缀和](01-arrays-and-hash.md) | 两数之和先查再记；多次区间和先建表再查。 |
| [双指针、滑动窗口与二分](02-pointers-and-search.md) | 证明为什么左边、右边，或一整半不再需要检查。 |

例如找有序数组中第一个 `>= target` 的位置。中点不够大时，它和它左边都不够大，所以一次排除一段。换成无序输入，同一句证明立刻失效。**题目给出的条件，比关键词更值得先读。**

## 学会把「下一步处理谁」写成状态和规则

| 学什么 | 能独立判断什么 |
|---|---|
| [链表、栈与队列](03-linear-structures.md) | 改引用前留住后继；最近的任务先处理还是最早的先处理？ |
| [树与图](04-tree-and-graph.md) | 需要子树的答案就递归汇总；需要无权最短距离就分层扩散。 |
| [回溯、动态规划与贪心](05-backtracking-dp-greedy.md) | 路径必须枚举、子问题可以复用，还是局部选择已经能证明安全？ |
| [排序与堆](06-sorting-and-heap.md) | 要全局有序，还是只要看到下一位或保住一个 Top K？ |

## 用任务规划器检验：数据结构不是孤立知识点

```d2
direction: down
foundation: 基础题：查表、缩区间、选下一步
practice: 进阶题：图、搜索决策、排序与堆
project: 小项目：带优先级的依赖规划器
foundation -> practice: 从单个状态练到状态之间的关系
practice -> project: 复用图的依赖关系和堆的出队规则
```

[综合项目](07-task-planner.md)把依赖图和优先队列接起来：先判断任务能不能执行，再选当前可执行任务里优先级最高的那个。它只产出顺序和阻塞列表，不实际运行任务。

**系统学**：按本页顺序，先读输入和运行结果，再自己写一次，最后跑测试。**面试速练**：先做数组和搜索，再做树图、决策、堆；时间不够也要解释复杂度和反例，别只抄答案。每道题复盘四句：输入前提是什么？我维护什么？为什么合法？什么反例会击穿错误写法？

从仓库根目录运行：

```bash
node code/algorithm-node/examples/01-arrays.ts
npm --prefix code/algorithm-node test
```

要求 Node 24+。运行示例和测试不需要安装 npm 依赖；类型检查和 lint 需要先 `npm ci`，详见[实验代码说明](../code/algorithm-node/README.md)。这是面向应用开发和面试的基础路线，不覆盖竞赛数学、高级图算法等专题。
