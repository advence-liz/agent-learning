# 网格 DP：障碍与最小代价

> [算法路线](00-guide.md) · 独立原创

在只能向右或向下走的网格里，每条路线都从上方或左方进入当前格；**数路线时把两个来源相加，找最低代价时从两个来源取最小值。** 障碍必须同时切断两种传播。

- [定义到达状态](#method)：计数和最小代价用不同的不可达值。
- [逐行手算](#worked-example)：用同一张地图对照两张表。
- [验证边界](#verify)：先验起终点，再验每个中间格。

## 只记录走到当前格的结果 { #method }

前提：给定非空 `m × n` 矩形网格，从左上到右下，只能向右或下移动，不得进入障碍。进入可走格支付其格值，起终点各支付一次；格值可以为负，因为每步都让行列下标之和增加，不可能绕圈。

| 当前格 | `ways[r,c]`：到达路线数 | `cost[r,c]`：到达最小总代价 |
| --- | --- | --- |
| 越界或障碍 | `0` | `+∞` |
| 可走的起点 | `1` | 起点格值 |
| 其他可走格 | `ways[上] + ways[左]` | `格值 + min(cost[上], cost[左])` |

最后一步来自上方的路线和来自左方的路线互不重叠，计数才能直接相加；若只求代价，接到当前格的花费一样，因此每个来源只须保留最便宜的走法。实现中若两个来源都是 `+∞`，直接保留不可达，不对有限整数哨兵做加法。先判障碍，再判是不是起点。

从上到下、每行从左到右填表，读右下角，时间 `O(mn)`、空间 `O(mn)`。只要数值时可滚动成两个长度为 `n` 的数组：更新前同列是上方，更新后前一列是左方，遇障碍记得把同列覆盖成 `0` 和 `+∞`，空间 `O(n)`。如果要恢复一条最便宜的路线，保存每格选中的前驱，从终点反追。

## 同一张地图可以算出四条路线和最低代价 11 { #worked-example }

```text
格值              到达路线数       最小到达代价
2  8  1  3        1  1  1  1       2  10  11  14
1  #  4  2        1  0  1  2       3   ∞  15  16
5  1  1  1        1  1  2  4       8   9  10  11
```

第二行第三列只能从上方来，故为 `1` 条、代价 `11 + 4 = 15`；终点的两边各送来 `2` 条，最小代价则由左方的 `10` 加终点的 `1` 得到。沿前驱可找出 `下、下、右、右、右`，总和是 `2+1+5+1+1+1=11`。

## 用枚举路线验证不可达和贪心反例 { #verify }

- **边界练习**：单格 `[-4]` 应得 `(1,-4)`；单格 `[#]` 应得 `(0,+∞)`。再把示例第二行全部封死，确认终点不可达，即使终点没有障碍。
- **贪心反例**：三行分别是 `1 1 100`、`2 100 1`、`2 2 1`。起点右邻比下邻便宜，但走右下一步必付 `100`；全局最低由 `下、下、右、右` 得到 `8`。

<summary>核验提示</summary>
