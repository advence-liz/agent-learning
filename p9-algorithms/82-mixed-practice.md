# 五道混合题：题目不告诉你该用哪种算法

> [算法路线](00-guide.md) · [核心算法框架](79-core-frameworks.md) · 独立原创

**先选方法，再写代码。** 每题先写四句话：题目给了什么关键条件？要交付什么？过程中要记什么？改掉哪个条件，原方法就不能照搬？写完再展开解析。小样例是用来验算的，不是用来证明方法对所有输入都成立的。

## 1. 连续几分钟的净流量最高？

每分钟的净流量是 `[3, -2, 5, -4, 2]`，负值表示流出。先求**恰好两分钟**的最高净流量。再改问：要让净流量至少为 `5`，最少需要连续几分钟？两个问题还能用同样的规则移走左端吗？

<details>
<summary>展开解析</summary>

第一问是 `3`，出现在 `[-2, 5]`。长度固定，用一次加、一减更新滑动窗口；负数不影响这条规则。第二问是 `1`，区间 `[5]`。如果仍用非负数版的可变窗口，扫到 `5` 时会先记下 `[3, -2, 5]`，丢掉 `3` 后剩 `3`，就停止缩窗，漏掉 `[5]`。先枚举核对，再看[含负数的进阶解法](80-sliding-window-practice.md#signed-solution)。

</details>

## 2. 同一张路线图，三个查询要返回什么？

路线只能沿箭头走：`A → B` 费用 `8`，`A → C` 费用 `1`，`C → B` 费用 `1`。分别回答：A 能到 B 吗？最少坐几段？最低费用是多少？如果加入优惠使某条边的费用为负，哪一个方法要重新选？

<details>
<summary>展开解析</summary>

能到，DFS 或 BFS 记录已发现节点即可。最少 `1` 段，按边数计，BFS 首次到达就能确定。最低费用是 `2`，走 A → C → B；非负权时用 Dijkstra，记录的是**可改进的暂定费用**，不是发现过就不再更新。负权改变的是第三问的前提，不能继续用 Dijkstra；前两问不比较费用。[树与图](04-tree-and-graph.md) · [加权最短路](23-dijkstra.md)

</details>

## 3. 一个包只有四格，怎么装最值？

一个零件占 `2` 格、价值 `5`，另一个占 `3` 格、价值 `6`。容量 `4`；每种零件只有一件，不要求装满。最高价值是多少？如果第一种零件改成不限数量，答案和记录方式怎么变？

<details>
<summary>展开解析</summary>

第一问是 `6`，只能装第二件；第二问是 `10`，装两件第一种。规模扩大时用背包动态规划，令 `dp[c]` 表示使用已处理物品、容量至多 `c` 的最大价值。两种问法可以用同一个状态定义；差异是原地更新的顺序：每件只能用一次就倒序，确保仍读到上一轮；不限数量就正序，允许读到本轮结果。如果仅第一种不限量，只对它改用正序。[背包](31-knapsack.md)

</details>

## 4. 两天搬完，最小的车要多大？

货物重量按顺序为 `[4, 1, 3, 2]`，每天搬一段连续的货物，最多两天搬完，单件不能拆。每天容量上限相同。最小容量是多少？找出一个条件，让你可以把一批候选容量直接排除。

<details>
<summary>展开解析</summary>

容量 `5` 可用 `[4, 1]` 和 `[3, 2]` 两天搬完；容量 `4` 至少三天。所以最小容量是 `5`。给定容量时，每天尽量装到放不下，能让当天搬完的前缀尽可能长；容量越大，可行性不会从真变回假，可以二分找第一个可行值。如果改成允许重新排列货物，容量可行性仍单调，但「按原顺序尽量装」不再是判定器。[二分答案](17-binary-search-answer.md)

</details>

## 5. 一间会议室，要的是场数还是收益？

会议有三场：`[0, 2)`、`[2, 4)`、`[0, 4)`；首尾相接不冲突，不能同时开两场。最初只问最多开几场；后来三个会议收益分别为 `2`、`2`、`7`，改问最大收益。原来的选择还安全吗？

<details>
<summary>展开解析</summary>

最多开 `2` 场；只数场数时，可以贪心选最早结束的会议，给后面留下最多时间。最大收益是 `7`，应该只开长会；按最早结束选短会只得到 `4`。多个区间时，可按结束时间排序，用动态规划比较「跳过当前会议」和「选当前会议、加上最后一个兼容前缀的最优收益」。[区间与贪心](29-intervals-and-greedy.md) · [带权区间调度](61-weighted-interval-scheduling.md)

</details>

## 复盘时，把错法缩成一个反例

再选一道刚答错的题，只改一条条件，写出原方法会给出的错误结果和正确结果。如果能解释**为什么错在某一步，而不只是记住换哪个名字**，再去做[阶段关卡](41-practice-checkpoints.md)练完整实现。
