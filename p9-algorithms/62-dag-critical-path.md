# DAG DP 与关键路径

> [算法路线](00-guide.md) · 独立原创

对没有环的先后依赖图，若资源不限、能并行的任务可以同时做，**任务最早开始时刻等于所有直接前置任务最早完成时刻的最大值。** 沿决定这个最大值的前驱回走，就能找到一条决定总工期的关键路径。

- [正向传播](#method)：汇合取最大，不把并行分支相加。
- [反向读表](#worked-example)：在同一张表上计算工期和余量。
- [测试前提](#verify)：分开验证并发、共享资源与环。

## 拓扑顺序保证每项任务的所有前置已算完 { #method }

设 `V` 项任务各有非负工期 `d[v]`，有 `E` 条依赖边。边 `u→v` 表示 `u` 完成后 `v` 才能开始，无额外等待、资源无限。项目从时刻 `0` 开始，须完成全部任务。先构造拓扑序：维护入度和零入度队列，出队后将后继的入度减一；若出队节点不足 `V`，存在环，不适用下面的转移。

令 `ES[v]` 为最早开始，`EF[v]=ES[v]+d[v]` 为最早完成。有前驱时 `ES[v]=max(EF[u]：u→v)`，没前驱时为 `0`。实现时初始化 `ES` 全为 `0`，按拓扑序完成每个 `u` 后向后继推送 `EF[u]`，取较大值。任何可行安排都不得早于任一前置的完成时刻；资源无限又保证所有任务同时安排在自己的 `ES` 上确实可行。

总工期 `T` 是所有终点任务的 `EF` 最大值，无任务时为 `0`。为每个有前驱的任务记下一个达到最大值的前驱（即使最大值是 `0` 也可记录）；从一个达到 `T` 的终点沿前驱回走到起点，反转得到一条关键路径。有平局时可能不止一条。

## 反推最晚时刻可以区分可推迟任务与关键任务 { #worked-example }

例子有 `A→C、A→D、B→D、C→E、D→E` 五条依赖。`A、B` 可并行，`D` 同时等待 `A、B`，`E` 同时等待 `C、D`。

| 任务 | 工期 | 最早开始 `ES` | 最早完成 `EF` | 最晚开始 `LS` | 余量 `LS-ES` |
| --- | --- | --- | --- | --- | --- |
| A | 3 | 0 | 3 | 0 | 0 |
| B | 2 | 0 | 2 | 3 | 3 |
| C | 4 | 3 | 7 | 3 | 0 |
| D | 2 | 3 | 5 | 5 | 2 |
| E | 1 | 7 | 8 | 7 | 0 |

在不延长项目的前提下，逆拓扑计算最晚完成 `LF[v]`：终点设为 `T`；内部点取所有直接后继 `LS` 的最小值。再算 `LS[v]=LF[v]-d[v]`。例如 `E` 最早在 `max(7,5)=7` 开始，项目第 `8` 个时间单位完成；反推 `D` 最迟在 `E` 的 `LS=7` 时完成，故它可迟至 `5` 开始。关键路径是 `A→C→E`，工期 `3+4+1=8`。余量表示单个任务在其他任务允许相应调整时的可推迟量，不可把多个任务的余量当成能独立同时用完的额度。

拓扑排序、正向和反向扫描合计 `O(V+E)` 时间；含邻接表空间 `O(V+E)`，若图已提供为邻接表，额外状态 `O(V)`。

## 用路径枚举检验工期，但不能用它代替资源调度 { #verify }

- **汇合反例**：两个独立前置工期分别为 `3` 和 `2`，同指向一个工期 `1` 的任务。无限资源时工期 `4`，不是把前置工期求和得到的 `6`。若三项任务共享一名全程独占的工人，真实工期才是 `6`，说明资源约束不能套用这组状态。
- **边界练习**：两个互不相连的任务工期 `2` 与 `5`，工期是 `5`，短任务余量 `3`；给两个任务互加依赖边，应报不能拓扑排序，不返回一个工期。

在随机小 DAG 上枚举所有从源到汇的路径并加节点工期，最长值应等于 `T`。再检查恢复路径的每条边确实存在、链上每项任务余量为 `0`。
