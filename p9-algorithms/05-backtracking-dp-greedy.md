# 回溯、动态规划与贪心：先判断哪些分支可以不算

> [算法路线](00-guide.md) · 独立原创
>
> **一句话：**要交付每条路径就回溯；不同路径通向同一个可复用的子问题就做动态规划；只有能证明某个局部选择不损失最优解，才用贪心。

## 三个问题看起来都在做选择，答案却不一样


### 要求列出子集，就保留路径并撤销选择

回溯（backtracking）里 `path` 是共享的工作区。`visit(start)` 先记录 `path` 的副本，再从 `start` 开始逐个尝试后续元素：`push` → 递归并把起点设为 `i+1` → `pop`。起点只向后走，所以同一组下标不会以不同顺序重复出现。忘记复制，所有答案会指向同一个数组；忘记撤销，兄弟分支会互相污染。按下标区分选择，输入值重复时可能产生相同值的子集。

`n` 个位置共有 `2ⁿ` 个子集；复制所有元素的时间和输出空间最坏都是 `O(n·2ⁿ)`，不计输出的栈和路径空间是 `O(n)`。要求真的列出来，不能因为结果大就把必要分支剪掉。

### 只问最少硬币数，保存「凑到某个金额的最优解」

对面值 `[1,3,4]`、目标 `6`，先选最大的 `4` 会变成 `4+1+1`；最优是 `3+3`。不用记录所有选币历史：只要面值是正整数且每种可无限用，「凑到 `t` 的最少枚数」与此前试过哪些路径无关。

设 `dp[t]` 为凑出金额 `t` 的最少枚数，`dp[0]=0`，其他先设为不可达 `Infinity`。任意可行解都可以拆掉最后一枚 `coin`，因此尝试每种不大于 `t` 的面值，取 `dp[t-coin] + 1` 的最小值。`t-coin < t`，从小到大填表即可。不可达的最终结果用 `-1` 表示。设目标为 `A`、面值种数为 `m`，时间 `O(A·(m+1))`、空间 `O(A)`（通常 `m>=1`，简写为 `O(A·m)` 时间）。这是按金额大小而非金额的二进制位数计的成本，超大目标不适合直接开表。

### 只问最多场不重叠会议，最早结束可以用交换论证

每场会议价值相同、区间是 `[start,end)`，问能安排的最多场数。取最早结束的会议，拿它替换任意最优安排的第一场：它不比那一场结束得晚，因此后续会议一个也不用丢。对剩余可安排会议重复这个论证，这才是贪心（greedy）安全的原因。不是所有「先选看起来最划算的」都对，刚才的硬币反例就是提醒。

实现把输入复制后按结束时间排序，再扫一遍。按常见比较排序成本计，时间 `O(n log n)`；本实现复制了数组，额外空间至少要给这份 `O(n)` 的副本，另有结果及排序内部开销。区间相接不冲突，因此只跳过 `start < lastEnd` 的项。见[三段实现](../code/algorithm-node/src/choices.ts)。
