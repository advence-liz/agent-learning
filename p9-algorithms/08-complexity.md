# 复杂度：先数操作，再决定要不要优化

> [算法路线](00-guide.md) · 独立原创

**同一个 `O(n)` 可以很慢，同一段双层循环也不一定是 `O(n²)`。** 复杂度回答的是规模增长时成本如何变动，不是这次跑了多少毫秒。

## 把循环翻译成一串可数的操作

枚举长度 `n` 数组里的不同位置对：外层固定 `i`，内层从 `i+1` 到末尾，一共检查 `n(n−1)/2` 对，所以是 `Θ(n²)`。相比之下，两端逼近的双指针也有两个变量，但每轮只移动一端，两个指针总共移动不到 `n` 次。窗口里即使嵌套 `while`，只要左右端都不回退，就不会重复付同一项的成本。

| 分析对象 | 计数方法 | 例子 |
|---|---|---|
| 最坏时间 | 选择让步骤最多的输入 | 无序数组找不到目标，必须扫完 |
| 额外空间 | 不算已有输入，明确是否算返回值 | 递归树深 `h`，最深同时存 `h` 层 |
| 摊销 | 在完整操作序列上记账 | 单次扩容线性；容量翻倍时多次追加的总搬运是线性 |

## 用反例对抗「嵌套等于平方」

把两端扫描的两次移动分别记账，再把数组复制、排序和递归临时存储都计入。不要把 CPU 时间、哈希平均访问和 JS 标准保证混在同一结论里。
