# 双指针、滑动窗口与二分：每一步都要说明排除了什么

> [算法路线](00-guide.md) · 独立原创
>
> **一句话：**指针挪动不是口诀。先写清没有被排除的候选是什么，再证明挪动不会把答案扔掉。

## 三道题把「移动边界」变成同一套推理

```bash
node code/algorithm-node/examples/02-pointers.ts
```

```text
sorted pair: [1,2]
longest unique: 2
first >= 2: 1
```

### 有序两数之和：太小时排除左项，太大时排除右项

`[1,3,4,7]` 找和 `7`：两端得 `8`，`7` 和当前最小项都太大，因此不可能再和候选区间里的其他项配对；右端左移。此时得 `5`，`1` 和剩余最大项都太小，因此左端右移，剩 `[3,4]` 正好命中。每轮丢一端，`O(n)` 时间、`O(1)` 额外空间。数组无序时不成立；如果为这一次查询先排序，得算排序成本，也要保留原下标。

### 滑动窗口：左边界不后退，才能保住无重复

扫 `abba`：第二个 `b` 到来时，窗口从 `ab` 缩到只剩最后一个 `b`；末尾的 `a` 上次出现于下标 `0`，已在窗外，不能让左边界退回下标 `1`。关键更新是 `left = Math.max(left, previous + 1)`，然后用 `right - left + 1` 更新答案。按哈希平均常数访问估算，时间 `O(n)`，空间 `O(u)`（`u` 是不同码点数）。代码用 `for...of` 按 Unicode 码点计数，不是 UTF-16 单元，也不是用户感知的字素簇。

### 二分边界：找的是第一处成立，不是任意一次命中

对 `[1,2,2,4]`，条件 `value >= 2` 的真假序列是「假、真、真、真」。循环维护 `lo` 左边已知不合格，`hi` 起（未越界的部分）已知合格，中间 `[lo,hi)` 待判定。`hi` 初始为 `n`，也就是全不合格时应返回的插入位置。

```d2
direction: down
mid: "检查 values[mid] ≥ target"
keep_left: "hi = mid，保留 mid 作为可能边界"
keep_right: "lo = mid + 1，mid 及左侧均不合格"
mid -> keep_left: 成立
mid -> keep_right: 不成立
```

当 `lo === hi`，第一个合格位置已经被夹出来。`O(log n)` 时间、`O(1)` 额外空间。这里 `hi = mid` 不是 `mid - 1`；后者会跳过还可能是答案的元素。见[完整实现](../code/algorithm-node/src/pointers.ts)。

2. 想用滑动窗口求「和至少为 K 的最短子数组」，输入可含负数；先尝试打破「不够就扩右边」的直觉。

<details>
<summary>提示</summary>

`[1,-1,3]`、`K=3`。常见非负数模板只在和达标时缩左：从 `[1,-1,3]` 去掉 `1` 后和掉到 `2` 就停，不会再丢掉 `-1`，于是错过 `[3]`。问题出在边界移动不再单调。先用暴力作对照。

</details>
