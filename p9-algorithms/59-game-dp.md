# 博弈 DP：轮到谁就站在谁一边

> [算法路线](00-guide.md) · 独立原创

两人轮流从数列两端取数、直到取空时，**用「当前玩家最多能领先多少」作为状态。** 取数之后视角交给对手，所以自己的收益要减去对手在剩余区间能取得的领先值。

- [推导换手规则](#method)：同一个状态适用于两个人。
- [手算最优首步](#worked-example)：用分差表预测对手会怎样拿。
- [验证终局](#verify)：对照负数、平局和贪心失败。

## 换手会把剩余区间的分差变号 { #method }

前提：双方知道整列整数，轮到就必须恰取左端或右端一个数，取到的数累进个人分数；没数则结束。双方都最大化自己的最终分数减对手的分数。总分固定，最大化分差也等价于最大化自己的总分。

令 `D[l,r]` 为**只看剩余区间**，轮到的玩家在双方都最优时能取得的「自己 − 对手」分差。空区间 `D[l,l-1]=0`。取左得到 `a[l]`，余下的 `D[l+1,r]` 是**对手的**领先值；取右同理：

```text
D[l,r] = max(a[l] - D[l+1,r], a[r] - D[l,r-1])
```

按区间长度 `1..n` 填表，单格自然等于该格的值。读 `D[0,n-1]`（空输入读 `0`），正数先手赢，负数后手赢，零平局。因为所有后续选择和可得分数只受剩余区间影响，不必记录之前两人的得分。时间 `O(n²)`、空间 `O(n²)`；只求分差可保留相邻两个长度层，空间 `O(n)`。要恢复双方最优走法，可保留选边记录，从整段开始每取一次就切换玩家。

## 拿走较小的端点反而能赢七分 { #worked-example }

数列 `3,9,1,2`，同一长度按左端点递增排列：

| 长度 | `D` |
| --- | --- |
| 1 | `3,9,1,2` |
| 2 | `6,8,1` |
| 3 | `-5,8` |
| 4 | `7` |

首取左端 `3`，剩余 `9,1,2` 给对手，对手最多领先 `8`，因此先手总分差是 `3-8=-5`。首取右端 `2`，对手在 `3,9,1` 中只能得到分差 `-5`，于是先手总分差是 `2-(-5)=7`。一条最优走法是先手拿 `2`、后手拿 `3`、先手拿 `9`、后手拿 `1`，比分 `11:4`。

## 用双方交替取极值的搜索验证 { #verify }

- **边界练习**：`[]` 平局，`[-4]` 先手输 `4` 分，`[-4,-2]` 先手赢 `2` 分。禁止跳过回合，所以不能把所有状态的初值当作可选的 `0`。
- **贪心反例**：在上面的四项例子里，总拿较大端点的先手首步选 `3`，后手拿 `9` 已能让先手输；换成 `[9,1,2]`，首取 `9` 的分差是 `8`，首取 `2` 是 `-6`，也不能反过来总拿较小端点。

<summary>核验提示</summary>

对短序列枚举两端选法到终局，统一按「先手 − 后手」记分；先手节点取最大，后手节点取最小。它和始终使用当前玩家视角的 DP 应得同一个根值。
