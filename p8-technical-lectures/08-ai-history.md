# AI 发展简史：从手写规则到能调用工具的系统

**AI 不是从 ChatGPT 开始的，也不是新技术来了就淘汰旧技术。** 七十多年来，变的是系统从哪里得到能力、能处理哪些任务、错了怎样验收。今天的 Agent 同时沿用了早期的搜索和规则、机器学习的模式识别，以及大模型的生成能力。

- [**规则与搜索解决边界清楚的任务**](#_2)：人先定义知识和约束。
- [**学习让系统从样本中得到能力**](#_3)：深度学习没有淘汰搜索，而是改变了评价候选的方式。
- [**预训练改变交互，工具接上执行**](#_4)：大模型能按语言描述适配任务，但真实读写仍由外部系统完成。

## 时间轴：能力来源在变化，旧方法仍在复用 { #_1 }

```d2
direction: down
rules: "规则与搜索\n表示知识 · 比较候选"
learning: "统计与深度学习\n从数据习得模式"
models: "预训练模型\n语言成为任务接口"
agent: "工具型 Agent\n模型 + 搜索 + 外部约束"
rules -> agent: 复用规则
learning -> models: 扩展到大规模预训练
models -> agent: 调用工具
```

**读图：** 这是能力组合，不是年代刻度。今天的工具型 Agent 会复用多条路线；不会因为有了新模型就不需要规则或检索。

| 阶段 | 代表节点 | 新的能力来源 | 当时仍难解决的问题 |
| --- | --- | --- | --- |
| 1950–1960 年代 · 提出问题与符号推理 | 1950 图灵论文；1955 年提案、1956 年达特茅斯项目；感知机、DENDRAL、ELIZA | 人写规则、表示知识、搜索候选解 | 规则维护成本高，换领域往往要重做 |
| 1980–2000 年代 · 专家系统、统计学习与专用搜索并行 | 专家系统商业热潮；1986 年反向传播代表论文；1997 年 Deep Blue 赢下六局对抗赛 | 一边继续做知识与搜索，一边从样本估计预测规律 | 专用任务表现强，不等于能迁移到开放任务 |
| 2012–2018 · 深度学习与预训练 | AlexNet、AlphaGo、Transformer、BERT | 用数据训练表示；在部分系统中结合搜索或强化学习 | 能力常仍以指定任务和数据集衡量 |
| 2019–2022 · 大模型进入通用交互 | GPT-2 后的规模化争论；2020 年 GPT-3 少样本；2022 年 ChatGPT；扩散模型发展 | 预训练模型用自然语言描述和示例适配不同任务 | 表达流畅不代表事实正确或能可靠执行 |
| 2023 至今 · 生成模型被接入工具与工作流 | 延续 2022 年预印本 ReAct 等工具交互研究，发展公开工具接口与工作流实践 | 读外部信息、调用工具、观察结果并继续 | 权限、失败恢复、成本与真实任务评测成为上线条件 |

这张表说的是几条重叠的路线，不是给某年划绝对分界。

## 人写规则时，系统擅长的是边界清楚的问题

图灵在 1950 年讨论「机器能思考吗」，把抽象争论转成一个关于可观察表现的模仿游戏。达特茅斯研究提案写于 1955 年，筹划的是 **1956 年夏天**的项目；它是研究议程的里程碑，并不是人工智能在那一天才出现。

给系统显式写规则，可以让它在定义好的范围内工作。DENDRAL 用领域知识辅助推断分子结构；ELIZA 的对话主要依靠脚本和词语模式，两者都不是今天的语言模型。专家系统后来进入商业应用，但知识获取、规则冲突和跨领域维护都成为负担。所谓「AI 寒冬」概括了部分时期投入和预期的回落，不表示全世界所有 AI 路线同时停摆。

## 从数据学习没有消灭搜索，而是给搜索换了组件

手写规则和学习并不是先后替换的两代。20 世纪 50 年代的感知机已经尝试从例子学习分类；1986 年的反向传播论文展示了怎样利用输出误差训练多层网络的内部表示。和规则系统同时演进的，还有从数据中学习的整条路线。

统计机器学习把问题从「手写每条规则」改成「从样本估计规律」：例如从已标注邮件学习如何区分垃圾邮件；拦截后的申诉或复核，仍由外部规则和流程决定。

1997 年 Deep Blue 赢下与卡斯帕罗夫的对抗赛，展示的是专用棋局搜索和评估，不是通用智能。2012 年 AlexNet 把深度卷积网络带到大规模图像识别竞赛的关键位置。2016 年 AlphaGo 以 4:1 战胜李世石，采用神经网络和搜索，并用自我对弈进行强化学习。把 Deep Blue 与 AlphaGo 放在一起看，比「旧搜索被新模型替代」更准确：**搜索仍在，但评价候选和决定优先顺序的方式变了。**

## 预训练让自然语言变成接口，工具才让模型参与执行

2017 年 Transformer 原论文主要评估机器翻译，并不是聊天产品。2018 年 BERT 展示了先用无标注文本预训练、再为下游任务微调的路径；2020 年 GPT-3 的少样本实验则展示了在不更新参数时用提示中的示例改变任务行为。2022 年 ChatGPT 的公开研究预览，把对话交互带到更多使用者面前。规模化争论及幻觉、数据与成本的反作用，单独见[《LLM 发展过程中的质疑与成长》](04-llm-development.md)。

同时，另一条路线把 AI 带到了聊天之外。2020 年的 [DDPM 论文](https://arxiv.org/abs/2006.11239)展示了通过逐步去噪合成图像；AlphaFold2 在蛋白质结构预测上的进展后来由[2024 年诺贝尔化学奖](https://www.nobelprize.org/uploads/2024/10/press-chemistryprize2024-3.pdf)表彰。两者提醒我们：**AI 的进步不只来自语言模型，也不总是以对话界面交付。**

随后增加的是系统层能力：例如模型先从知识库查证，再决定是否需要计算，读回结果后输出或继续。外部执行器可以提供权限、上限和记录；这些不是模型「更聪明」就会自动拥有的能力。可对照[《Agent 运行线路图》](01-agent-runtime-map.md)、[《AI 行业进展与代表应用》](10-ai-industry-watch.md)与[《AI 怎么从试用走到业务流程》](09-ai-business-adoption.md)。

### 模型会回答，不等于它查过资料 { #answer-vs-evidence }

**训练让模型学会生成回答；要证明某条政策适用，仍要看本轮拿到了什么依据。** 同样问「这笔订单还能退吗？」，模型可能面对三种不同的输入：

```d2
direction: down
question: 这笔订单还能退吗？
prior: "没有政策原文\n不能确认适用条款"
old: "给了旧版政策\n能引用，未必适用"
current: "查到生效政策\n还要核对订单条件"
question -> prior: 只给问题
question -> old: 人把原文贴进对话
question -> current: 工具查回原文
```

**读图：** 三条线是三种输入，不是三个必经步骤。没有资料时，模型仍能靠训练学到的模式生成看似合理的回答。贴资料或调用工具，是给本轮增加上下文，不是当场重新训练模型。

比如，旧版写「签收后 30 天」，现行条款写「这个类目的订单限签收后 15 天」。模型即使准确引用了旧文字，也可能对第 20 天提出的退货请求给出错误答复。**查到原文以后，再核对生效日期、适用类目和订单条件；缺条件就说缺什么。** 能引用不等于结论正确，能查到也不等于有权退款。想看生成原理，读[《LLM 和 Agent》](../p0-core/01-llm-and-agent.md)；想看工具结果怎样回到模型，读[《Agent 运行线路图》](01-agent-runtime-map.md)。
