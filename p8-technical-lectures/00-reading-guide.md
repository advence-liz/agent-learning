# 科普导读：按你想回答的问题选读

**想知道 AI 从哪来、Agent 怎么工作，还是某个成果值不值得用？从对应的问题开始，不必把九篇全部读完。** 如果是第一次接触 Agent，先看简史建立背景，再看运行线路图；其余按需要展开。

- **想知道 AI 与 Agent 从哪来**：先读[AI 发展简史](08-ai-history.md)建立时间轴；再按兴趣看[LLM 争论史](04-llm-development.md)里证据怎样改变观点，或从[Agent 词源](05-agent-etymology.md)分清自主和委托。
- **想知道 Agent 怎么工作**：先读[Agent 运行线路图](01-agent-runtime-map.md)认清模型、运行时、工具和状态的分工；再按需求选[代码库检索](02-codebase-search.md)或 [Harness 指南](07-claude-code-harness-guide.md)。配 Harness 不必先会 PageRank。
- **想判断新成果值不值得用**：从[四层证据](06-llm-capability-boundaries.md#c7)分清基准、交付物、真实试验和就业观测，再用[11 月行业观察](10-ai-industry-watch.md)练习。只想做试点，可以直接翻[业务落地](09-ai-business-adoption.md)，看验收、成本和执行权限。

## 拿到一个 AI 需求，先问哪一步值得交给模型

先把需求拆成「怎么算、怎么查、是否要动手」。下面用同一个虚构售后流程判断：

```d2
direction: down
job: 一个售后需求
rule: "规则算得清\n用代码判定"
assist: "需要找依据\n先检索并起草"
agent: "查询路径不固定\n用有限的只读 Agent"
action: "如果要退款\n另走授权与执行"
job -> rule: 期限计算
job -> assist: 政策解释
job -> agent: 例外调查
job -> action: 涉及写入
```

**读图：** 退款权限是独立判断，不是从规则、检索到 Agent 一路升级后自动得到的权力。

| 需求 | 先试的最小做法 | 该验收什么 |
| --- | --- | --- |
| 按明确条款核对订单是否超过退货期限 | **规则**：日期和条款明确，先用代码计算，不必用 Agent。 | 边界日期、时区、节假日和例外条款。 |
| 从最新版政策里找依据、解释为什么不能退 | **检索 + 草稿**：先找可引用的政策，由模型组织回答。 | 引用是否对应到正确政策和生效日期；没找到时能否明确说不知道。 |
| 情况复杂，要反复查订单、物流和政策例外 | **限定范围的 Agent**：只有当下一步查询取决于前一步结果时，才让模型选择；默认只读、到上限就交人。 | 所查依据、人工接手所需信息，以及是否始终留在授权范围内。 |
| 把钱退回去 | **受控执行**：这是单独的授权决定，不是让 Agent 更自主一点。可以让规则流程按审批结果执行。 | 实际订单状态和付款回执；失败时不能把不确定状态说成成功。 |

这里的做法是教学示例，不是产品功能声明。想看实现差别，读[《Workflow 和 Agent》](../p2-agent-basics/05-workflow-vs-agent.md)；想看怎么放量与接管，读[业务落地篇](09-ai-business-adoption.md)。
