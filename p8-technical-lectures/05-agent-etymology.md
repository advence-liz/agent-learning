# Agent 的前世今生：自己行动，还是替人行动？

理解 AI Agent，可以先分开两个问题：**系统能自己决定哪些步骤，以及它受谁委托、被允许做哪些事。** 前者谈能力，后者谈权限。能自主完成任务，不等于有权自主执行。

## 一个词，既能指行动者，也能指受托者

英语 *agent* 的词源可追到拉丁语 *agere*（驱动、做、行动）的现在分词 *agēns*。英语里的 *agent* 可以指产生某种作用的人或物，例如 *cleaning agent*（清洁剂），也可以指代表他人办事的人，例如 *travel agent*（旅行代理）。第一种用法不要求有意图；第二种强调代表谁办事，并不意味着代理者不能自行判断。

哲学里的 *agency* 关注行动者如何行动。经济学的委托—代理问题则关注：如果委托人不能完全观察代理者的行为，两者的目标又可能不同，应该怎样设计激励与约束。两条线问的不是同一个问题。

## 软件 Agent 把两条线放进同一套系统

| 要分清的问题 | 在软件里看什么 | 以虚构的日历助理为例 |
| --- | --- | --- |
| 它能自己决定什么？ | 是否能根据工具结果调整下一步 | 查到时间冲突后，继续寻找备选时段 |
| 它代表谁行动？ | 谁给出目标和权限，哪些操作需要另行确认 | 能读取空闲时段，不代表可以替用户发邀请 |

早期软件代理研究已在讨论自治、对环境变化的响应，以及主动为目标采取行动。大模型提供了一种让系统根据自然语言目标和中间结果选择下一步的方式。至于选出来的动作能不能执行，仍要看外部的权限和确认规则。

## 「智能体」和「代理」，强调的不是同一件事

「智能体」容易让读者想到系统怎样感知、判断和行动；「代理」容易让读者想到它替谁办事、权限到哪里。比统一译名更有用的是直接交代：**哪些步骤由系统自主决定，哪些副作用需要谁批准。** 想看一次任务具体怎么跑，可接着读 [Agent 运行线路图](01-agent-runtime-map.md)。
